# Public website behavior datasets for optimization prototypes

## Which datasets can support realistic interaction and conversion analysis?

### Takeaway

Use the Google Analytics 4 ecommerce BigQuery sample for an accessible event/funnel prototype, Coveo SIGIR eCom 2021 for rich sequential product discovery and purchase-intent experiments under research-only terms, and UCI Online Shoppers for a genuinely permissive, lightweight purchase-intention baseline. YOOCHOOSE and Retailrocket are useful secondary sequence datasets, but their reuse terms need more scrutiny than their easy download links suggest. None of these datasets records pointer hover dwell on a pricing card, price-plan comparison visibility, a video-credit exhaustion moment, or randomized UI treatment assignment. They can validate pipeline mechanics and generate clearly labeled hypotheses, not establish VDO-X-specific behavior or causal revenue lift.

### Cited Findings

- **GA4 Google Merchandise Store sample (best end-to-end analytics schema example).** Google's official guide identifies the public BigQuery table `bigquery-public-data.ga4_obfuscated_sample_ecommerce`; it contains three months of sample Google Merchandise Store events from 2020-11-01 through 2021-01-31, and was last updated in August 2026. It is obfuscated sample data intended to emulate real collection; Google warns of placeholders, imperfect internal consistency, and differences from the live demo account. Exploring it requires a Google Cloud project and BigQuery, with Sandbox/free usage available. [Google Analytics BigQuery sample guide](https://developers.google.com/analytics/bigquery/web-ecommerce-demo-dataset)
- The GA4 export is event-row based: daily tables use `events_*` and include event names and nested parameters/items. Google's official examples show page-view sequence analysis and ecommerce event querying; its instrumentation documentation specifies item-list and product interactions such as `view_item_list`, `select_item`, and `view_item`, with item IDs, names, prices, and quantities where sent. [GA4 BigQuery query examples](https://developers.google.com/analytics/bigquery/basic-queries), [GA4 ecommerce measurement](https://developers.google.com/analytics/devguides/collection/ga4/ecommerce)
- The data is openly queryable as a public BigQuery sample, but the dataset guide does not state an explicit license for the *data*. The guide's CC BY 4.0 notice applies to Google documentation, not automatically to dataset contents. Treat it as suitable for local prototyping/querying; confirm the data terms before redistributing or using it commercially as training data. [Guide and its licensing notice](https://developers.google.com/analytics/bigquery/web-ecommerce-demo-dataset)
- **Coveo SIGIR eCom Data Challenge 2021 (richest product-session interactions).** Coveo's original repository describes 36 million events; the browse event file has nearly 5 million anonymized shopping sessions. Records include a hashed session ID, event type, product action (`detail`, `add`, `purchase`, `remove`), hashed SKU, shifted timestamp, and hashed URL. Query interactions include returned/clicked products; catalog features include category, a 10-quantile price bucket, and text/image vectors. The source warns that events may be out of chronological order and front-end collection has minor inconsistencies. [Coveo dataset README](https://github.com/coveooss/SIGIR-ecom-data-challenge/blob/main/README.md)
- SIGIR's official challenge page frames the data around session recommendation and add-to-cart purchase-intent tasks; the original challenge paper reports more than 30 million fine-grained events. Access/use is conditioned on the challenge's registration/fair-use terms for research and educational purposes; it forbids uses outside those terms and attempts to re-identify/link people, brands, or entities. This is not a general commercial-use license. [SIGIR 2021 data/task page](https://sigir-ecom.github.io/ecom2021/data-task.html), [original challenge paper](https://arxiv.org/abs/2104.09423), [Coveo usage conditions](https://github.com/coveooss/SIGIR-ecom-data-challenge/blob/main/README.md)
- **UCI Online Shoppers Purchasing Intention (clearest permissive baseline).** UCI documents 12,330 sessions from a one-year period, one session per user, with 17 features and a purchase/revenue target; 1,908 sessions are positive and 10,422 negative. Attributes include page counts/durations, bounce/exit rates, traffic type, browser, operating system, region, visitor type, weekend/month, and special-day proximity. It is CC BY 4.0, permitting sharing/adaptation, including commercial use, with attribution. [UCI dataset page](https://archive.ics.uci.edu/dataset/468/online)
- UCI is a compact session-feature table, not a raw event stream: it cannot recover event order, inspect a specific plan card, infer hover or viewport attention, or test the effect of a UI redesign. Its target can support baseline conversion propensity, calibration, segmentation, and pipeline demonstrations, but the dataset is from 2018 and domain-specific. [UCI dataset documentation](https://archive.ics.uci.edu/dataset/468/online)
- **YOOCHOOSE / RecSys Challenge 2015 (large event sequences, unclear reuse rights).** The original challenge paper describes six months of activity from a large European retailer, about 9.51 million unique sessions, 33,040,175 click records, and 1,177,769 purchase records. Click rows provide session, timestamp, item ID, and item category; purchase rows provide session, timestamp, item ID, price, and quantity. [Original RecSys Challenge paper](https://dbs-home-page.s3.amazonaws.com/dbs/papers/recsyschallengeyc2p.pdf)
- A later Zenodo deposit makes the files easy to obtain (about 440.8 MB), but its record describes educational use and has no clear explicit license field. A download link or educational statement is not blanket permission for commercial reuse, redistribution, or model training; locate and comply with the original challenge terms before use. [Zenodo YOOCHOOSE deposit](https://zenodo.org/records/7412233), [original RecSys Challenge page](https://recsys.acm.org/recsys15/challenge/)
- YOOCHOOSE can support next-item/session sequence analysis, click-to-purchase funnels, and price/quantity-associated purchase outcomes. It has no viewport geometry, hover, demographic profiles, controlled design variants, or causal experiment assignment; its 2015 age and retail domain limit direct transfer to a video-generation subscription funnel. [Original RecSys Challenge paper](https://dbs-home-page.s3.amazonaws.com/dbs/papers/recsyschallengeyc2p.pdf)
- **Retailrocket (event stream plus catalog, license not resolved).** The Kaggle dataset card describes web events, item properties (including text), and a category tree. A Kaggle source page requires account access to download. Secondary dataset documentation describes 2,756,101 events over 4.5 months from 1,407,580 visitors: `view`, `addtocart`, and `transaction`, plus visitor/item/timestamp IDs; this is a useful session funnel and item-context dataset. [Kaggle dataset card](https://www.kaggle.com/datasets/retailrocket/ecommerce-dataset), [dataset documentation mirror with summary](https://github.com/caserec/Datasets-for-Recommender-Systems/blob/master/Processed%20Datasets/RetailrocketEcommerce/README.md)
- The above accessible sources do not establish a reliable license for the original Retailrocket data. Kaggle presence, a Zenodo mirror, or a permissive license on a third-party processed copy must not be assumed to license the source data. Use only after verifying rights with the dataset owner/source; keep it out of commercial or model-training pipelines until then. [Kaggle dataset card](https://www.kaggle.com/datasets/retailrocket/ecommerce-dataset), [Zenodo mirror](https://zenodo.org/records/10998222)

### Inferences

- For the product's first analytics-demo flow, GA4 is the most useful schema template because its real-world event model includes event names, parameters, items, traffic source and device context. The sample's obfuscation and age mean findings should be explicitly labeled as demonstrations, not VDO-X observations.
- Coveo is the best public research benchmark for interesting session narratives such as repeated product-detail views before add-to-cart, query-to-click patterns, and category/price-bucket interest. Its research-only terms make it unsuitable as a general commercial source unless Coveo separately authorizes the intended use.
- UCI is the best safe baseline to bundle in an open prototype because it has an explicit CC BY 4.0 license and a small file, but it demonstrates only session-level conversion classification—not behavioral instrumentation or sequential attribution.
- YOOCHOOSE and Retailrocket can help exercise an event ingestion/sequence pipeline if terms are cleared. Their fields still cannot justify claims like “users hovered over plan 3 more” or “show the paywall after the third generated video.” Those require VDO-X first-party events and experiment assignment.
- Model labels should distinguish: (1) dataset facts, (2) derived observations, (3) hypotheses/strategies, and (4) measured experiment outcomes. Public datasets support the first three in their own domains; only properly instrumented VDO-X data and controlled tests support VDO-X-specific decisions and lift claims.

### Gaps

- No reviewed public dataset provides the specific pricing-card hover duration / mobile equivalent, viewport exposure, generated-video count before paywall, credit balance at paywall, user preference category, and randomized before/after UI treatment data needed for the user's examples.
- GA4 public dataset data-license status should be verified against the BigQuery dataset's actual terms before redistribution or commercial training; Google docs' CC BY notice is not proof of data licensing.
- YOOCHOOSE needs its original challenge's current access and reuse terms confirmed before any use beyond limited research. Zenodo's deposit record is not a substitute for source rights.
- Retailrocket's original dataset license remains unresolved from primary sources. A downstream mirror may change formatting but cannot grant rights it does not hold.
- Public ecommerce samples differ from VDO-X's video generation, consumption cost, credits, subscription plans, and payoff moments. Treat them as engineering/research fixtures, not evidence about VDO-X customer behavior.

## What should VDO-X instrument to answer the target questions?

### Takeaway

Collect a small, explicit, privacy-conscious event model that records exposure and meaningful behavior, along with outcomes and experiment assignment. Track desktop pointer dwell and mobile viewport exposure as different signals; neither is a direct measure of desire. To learn when a paywall works, link generation milestones, remaining credits, paywall exposure, dismissals, checkout, and purchase. Ask for optional demographic/preference information only when it has a clear user benefit and a valid consent/legal basis; infer neither age nor wealth from behavioral proxies.

### Cited Findings

- GA4's ecommerce documentation demonstrates explicit event instrumentation for product-list and item interactions, plus item identifiers and values. A similar event taxonomy can be adapted for plans, credit bundles, and generated videos, provided the application captures those events at source. [GA4 ecommerce measurement](https://developers.google.com/analytics/devguides/collection/ga4/ecommerce)
- GA4's BigQuery examples show sequence queries over events and timestamps; this provides a practical pattern for deriving user journeys from an event table rather than guessing from aggregate page counts. [GA4 BigQuery query examples](https://developers.google.com/analytics/bigquery/basic-queries)
- Coveo's dataset demonstrates how session, timestamp, event/action, item identity, and query/click-result relationships allow richer analyses than aggregate page-view counts. [Coveo SIGIR eCom README](https://github.com/coveooss/SIGIR-ecom-data-challenge/blob/main/README.md)

### Inferences

- Suggested core events: `pricing_view`, `plan_card_impression`, `plan_card_pointer_enter`, `plan_card_pointer_leave`, `plan_compare`, `generation_started`, `generation_completed`, `credit_balance_changed`, `paywall_view`, `paywall_dismissed`, `checkout_started`, `purchase_completed`, and `subscription_cancelled`.
- Include event time, anonymous/session ID, consent state, page/route, plan/offer variant, viewport dimensions, device class, experiment ID/arm, generation count and remaining-credit bucket at paywall, and plan/offer ID. Keep stable user identity optional and access-controlled; avoid collecting raw credentials or sensitive traits in analytics.
- On mobile, record which card was sufficiently visible and for how long using intersection/viewport exposure. On desktop, pointer entry/dwell can indicate attention, but should be paired with actual selection and downstream outcomes; a hover alone is an ambiguous signal.
- Instrument a minimum set before redesigning, then run an experiment that randomizes presentation/trigger timing. Compare outcomes by assignment, not only by observed exposure, to avoid mistaking self-selection for the effect of the strategy.
- The dashboard should show “observed,” “hypothesis,” and “tested” states. If a source lacks an event, generate a data-gap recommendation (for example, add mobile card impressions before inferring plan interest) rather than filling the gap with a synthetic claim.

### Gaps

- The sources above do not specify VDO-X's current event instrumentation, consent framework, identity model, experiment tooling, or actual UI. These must be inspected in authorized project data or implemented with explicit product decisions before analysis can begin.
- A public ecommerce dataset cannot reveal VDO-X's optimal paywall timing, credit grants, pricing, or personalization segments. These require VDO-X-specific data and randomized evaluation.
