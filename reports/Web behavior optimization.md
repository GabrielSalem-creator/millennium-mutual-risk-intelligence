# Turn browsing signals into tested decisions

A useful behavior-intelligence product should pair each **specific observation** with its source and a **creative, testable next decision**; it should never mistake a hover, viewport exposure, or platform metric for user intent. VDO-X’s Nov 7–13 event log already shows a real retry pattern: **73 adjacent `video_generate_fail → video_generate_start` transitions**, but it records no pricing-plan, hover, scroll, or paywall events. That means the deck can show real generation behavior and an explicit plan-attention data gap, while presenting pricing layouts and paywall timing as hypotheses. Public datasets can exercise sequence analysis, but none found supplies VDO-X’s missing plan visibility or credit-timing events. The strategy loop should measure those events, generate multiple options, test one change at a time, and keep only decisions that improve durable contribution without harming task success, refunds, or trust.

## VDO-X has a retry signal, not a pricing-attention signal

In the seven days ending Nov 13, 2026, VDO-X’s `public.events` table held **4,708 event rows across 1,342 sessions**. It recorded 459 `video_generate_start` events across 189 sessions, 364 `video_generate_complete` events across 155 sessions, 85 `video_generate_fail` events across 43 sessions, and 299 `auth_signup` events across 277 sessions. The log also contained **73 adjacent fail-to-start transitions** and 278 adjacent complete-to-start transitions. Those are transition counts, not unique people or causal effects; sessions can contain several attempts and both success and failure. The most actionable observation is that failure is often followed by another attempt. A sensible first experiment is a more helpful failure state that keeps the user’s settings, states whether credits were refunded, and offers clear retry/edit choices. Compare it with the current experience on successful completion per eligible session, repeat failures, refunds, and abandonment. (Internal source: VDO-X Supabase `public.events`, selected fields `event_name`, `session_id`, and `created_at`, queried Nov 14, 2026.)

The event taxonomy contains `page_view`, `session_start`, `auth_signup`, `auth_login`, `video_generate_start`, `video_generate_complete`, `video_generate_fail`, and `client_error`; it contains no plan-hover, plan-exposure, scroll-depth, paywall-view, or credit-balance event. Therefore, **“people hover on plan 3 more” is not a VDO-X finding**. It is a useful instrumentation question. The platform metrics separately show a provider/model failure spike on Nov 8: `vivix-ai / vivix-w1-fast-i2v` failed 41 of 49 video rows (83.7%) versus 13 of 84 (15.5%) on Nov 9–13, about 5.4 times the later rate. That is a historical operational signal, not an explanation of customer preference. The seven-day totals in `daily_metrics` and `videos` also differ, so metric definitions and retry handling should be reconciled before presenting them as a single funnel. (Internal sources: VDO-X Supabase `public.videos` and `public.daily_metrics`, aggregate fields only, queried Nov 14, 2026.)

## Measure exposure separately from attention and intent

On desktop, pointer entry and dwell time can be recorded as pointer interaction. On touch devices, the comparable event is a plan card’s geometric visibility for a defined interval, not a fabricated “hover.” The browser’s Intersection Observer reports how much an element intersects a viewport, while Page Visibility can exclude time when the tab is hidden; neither proves that someone looked at or understood a plan. ( [Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API), [Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API), [GA4 ecommerce events](https://developers.google.com/analytics/devguides/collection/ga4/ecommerce) )

An event record should distinguish plan exposure, pointer entry/exit, explicit plan selection, checkout start, purchase, credit balance, paywall view/dismissal, and generation completion. Keep session, page, plan, device/pointer type, consent, experiment variant, timestamps, and coarse exposure duration together so each finding can cite its denominator and source. Use only the fields needed for the decision. Do not infer age, wealth, or willingness to pay from behavior; let a person optionally state their use case, keep all prices and essential terms visible, and offer a non-personalized path. NIST’s AI Risk Management Framework emphasizes privacy, autonomy, transparency, fairness, and accountability; the FTC documents hidden fees, false urgency, and obstructive flows as dark-pattern risks. ( [NIST AI RMF 1.0](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.100-1.pdf), [FTC dark-pattern report](https://www.ftc.gov/news-events/news/press-releases/2022/09/ftc-report-shows-rise-sophisticated-dark-patterns-designed-trick-trap-consumers) )

## Make each idea a distinct before-and-after test

For the plan-layout idea, the observation must first be that exposure is missing or uneven—not that plan 3 is preferred. Instrument the current layout, then test a stacked comparison against the existing three-across layout while holding plan order, price, and copy constant. The “after” can improve legibility and add a neutral comparison anchor, but the success metric is paid contribution per eligible visitor alongside comprehension, abandonment, refund, and accessibility guardrails; extra scrolling alone is not success. For paywall timing, test a clear optional offer after a successful free result or at a transparent credit boundary against the current trigger, with the same offer and price in both arms. Measure contribution over a defined window, first-result success, repeat use, refunds, and cancellations—not just immediate checkout clicks. These are **proposed hypotheses**, not proven lifts.

Each card should show: observed sentence; “what else could explain this?”; data table/fields/window; proposed UI before/after; primary outcome; user-value guardrails; and state (`observed`, `hypothesis`, `testing`, or `validated`). Randomized assignment supports causal conclusions; before/after dashboard movement does not. Microsoft's experimentation guidance calls for objective metrics, guardrails, data-quality checks, sample-size planning, and sample-ratio checks. A contextual bandit belongs later, after trustworthy logging and randomized baselines; it needs action probabilities, outcomes, a randomized holdout, and guardrails for delayed value. ( [Microsoft pre-experiment guidance](https://www.microsoft.com/en-us/research/articles/patterns-of-trustworthy-experimentation-pre-experiment-stage/), [Microsoft during-experiment guidance](https://www.microsoft.com/en-us/research/articles/patterns-of-trustworthy-experimentation-during-experiment-stage/), [Vowpal Wabbit estimators](https://github.com/VowpalWabbit/estimators) )

## Use public datasets as fixtures, not VDO-X evidence

The **UCI Online Shoppers Purchasing Intention** dataset offers 12,330 sessions and a CC BY 4.0 license, so it is a practical, permissively reusable baseline for session-level conversion work; its 2018 aggregate features do not contain raw event order or plan attention. **Google’s GA4 ecommerce sample** is useful for event-schema and funnel prototypes, but it is obfuscated sample data and the data guide does not establish an explicit license for redistribution or model training. **Coveo SIGIR eCom 2021** has rich product-search sequences and price buckets, but its challenge terms are research/education-oriented rather than a general commercial license. YOOCHOOSE and Retailrocket can exercise event-sequence code, but their original reuse terms need verification. None measures pricing-card hover, viewport attention, credit exhaustion, or randomized VDO-X treatment. ( [UCI dataset](https://archive.ics.uci.edu/dataset/468/online), [GA4 sample guide](https://developers.google.com/analytics/bigquery/web-ecommerce-demo-dataset), [Coveo dataset terms](https://github.com/coveooss/SIGIR-ecom-data-challenge/blob/main/README.md), [SIGIR dataset task](https://sigir-ecom.github.io/ecom2021/data-task.html), [YOOCHOOSE source](https://recsys.acm.org/recsys15/challenge/), [Retailrocket dataset card](https://www.kaggle.com/datasets/retailrocket/ecommerce-dataset) )

## Conclusion

The platform’s creative advantage should come from turning one measured signal into several different, evidence-linked options—not from sounding certain about unmeasured psychology. VDO-X can start with its real retry loop and failure incident, then add the missing plan-exposure, credit-boundary, paywall, and treatment-assignment events. Each before/after should be labeled as a proposal until a controlled test measures what changed. Public data can help build and debug that pipeline; only consented, well-instrumented VDO-X experiments can tell the product which decision works for its own users.
